1. Executive Summary

RulePilot AI turns static company policies and SOPs into executable workflows. A user uploads a policy PDF; RulePilot extracts business rules as structured JSON, generates a visual workflow, checks real business requests against those rules, returns a decision with an exact policy citation, and produces the next required action (for example, an approval request).

Core principle: the LLM interprets policy; a deterministic rule engine decides.

2. Problem

Organizations hold HR, expense, leave, procurement, travel and compliance documents that describe a process but do not run it. Employees must manually work out which policy applies, what conditions to check, which documents are missing, who must approve, and what happens next.

Impact: slow decisions, inconsistent enforcement, missed approvals, compliance errors, and dependence on experienced staff.

3. Goals and Non-Goals

Goals

  • Convert a policy PDF into structured, machine-readable rules.
  • Generate a visual workflow from those rules.
  • Evaluate a business case deterministically and explain the result.
  • Show clickable citations (document, section, page) for every decision.
  • Generate the next action and show the agent pipeline running.
  • Deploy on Vercel at zero infrastructure cost.

Non-goals (hackathon) Enterprise SSO, complex permissions, custom OCR, fine-tuning, microservices/Kubernetes, mobile apps, payments, production-scale security, drag-and-drop workflow editor.

4. Target Users

  • MVP: HR, finance, operations, procurement and compliance teams; SMEs and enterprises.
  • Future: healthcare, universities, banks, logistics, government, insurance.

5. MVP Use Case: Employee Expense Reimbursement

Sample policy rules

  • Receipt required above PKR 5,000.
  • Manager approval required above PKR 50,000.
  • Finance approval required above PKR 100,000.
  • Hotel limit PKR 25,000 per night.
  • Claims must be submitted within 14 days.
  • International travel requires pre-approval.

Example

Input Output

Reason: Amount exceeds PKR 50,000
Evidence: Travel Expense Policy, Section 4.2, Page 6

6. Functional Requirements

ID Requirement Priority
FR-1 Policy upload. PDF upload (type and size validated), stored in Supabase Storage. Must
FR-2 Text extraction. Page-aware extraction via pdfjs-dist or unpdf, keeping document name, page, section (if detectable) and chunk content. Must
FR-3 Rule extraction. Gemini converts policy text into structured JSON rules (see §8). Must
FR-4 Workflow generation. Rules become React Flow nodes and edges: start, decision, condition, action, approval, completion. Must
FR-5 Policy RAG. Chunk, embed, store in pgvector, retrieve evidence. Each chunk carries document_id, page_number, section, content. Policy evidence takes priority over the LLM's general knowledge. Must
FR-6 Case form. Employee name, category, amount, receipt, manager approval, finance approval, date incurred, date submitted, international travel, pre-approval. Manually built for MVP. Must
FR-7 Deterministic rule engine. Application code executes structured rules; supports multiple simultaneous violations. Must
FR-8 Evidence and citations. Every decision shows reason, source, section and page; clicking a citation opens the policy text. Must
FR-9 Agent timeline. Live status per agent: waiting, processing, completed, failed. Must
FR-10 Action generation. Approval requests and missing-document requests; copy/download. Must
FR-11 Webhook automation. Webhook to Make to email a manager. Core flow must work if it fails. Nice
FR-12 Extras. Auth (Supabase), DOCX, OCR, multi-policy, workflow editing/versioning, audit report, analytics, dynamic forms. Nice

7. Agent Architecture

Agent Responsibility
Document Parser Extract text, preserve page references, detect sections, prepare chunks.
Policy Extraction Identify rules, conditions, thresholds, required documents, approvals and actions; return JSON.
Evidence Semantic search over chunks; return exact supporting text with citations.
Workflow Turn rules into nodes and edges.
Decision Engine Execute rules deterministically; flag compliant or non-compliant and list missing requirements.
Action Choose the next action; draft approvals, document requests, notifications. 
PDF → Parse → Chunk → Embed → pgvector
                         ↓
         Policy Extraction → Structured Rules → Workflow
                                   ↓
   Case → Rule Engine → Decision + Evidence → Action → (Webhook)

Why deterministic: predictable behavior, less hallucination, easier testing, transparent decisions.

11. API Routes

Route Purpose
POST /api/documents/upload Upload and store PDF, start extraction
POST /api/documents/process Extract text, chunk, embed, save
POST /api/rules/extract Gemini rule extraction, store rules
POST /api/workflows/generate Rules to React Flow JSON

POST /api/actions/generate Draft action, optionally fire webhook

12. User Flow and Screens

Flow: upload policy → processing summary ("6 pages processed, 14 rules detected, workflow generated") → view workflow → run new case → agent timeline runs → decision with citation → generate approval request → (optional) webhook.

Screen Contents
Dashboard Policies, workflow count, case count, recent activity
Upload Policy Drag-and-drop, progress, agent status
Policy Intelligence Document, extracted rules, sections, citations
Workflow Builder React Flow workflow
Execute Case Form, agent timeline, decision, evidence, generated action

Design direction: serious B2B SaaS. Clean, minimal, neutral palette, cards, subtle animation, clear status indicators. Built around policies, workflows, decisions, agents and evidence, not a chat box.

13. Non-Functional Requirements

  • Performance: policy analysis about 10–30 s for small documents; case execution within a few seconds.
  • Reliability: demo must run on predefined data. Keep backups of extracted rules, workflow, demo PDF and sample requests.
  • Explainability: every decision answers what happened, why, which rule, where it is written, and what happens next.
  • Security: server-side keys, sample data only, file type and size limits, sanitized extracted text, no real confidential data.
  • Auth: optional (Supabase Auth); never ahead of the core flow.

17. Risks and Mitigations

Risk Mitigation
LLM extracts wrong or incomplete rules Validate JSON schema; keep pre-verified sample rules as fallback
PDF sections not detected reliably Fall back to page-level citations; use a clean demo PDF
Gemini or embedding free-tier limits Cache results; precompute demo embeddings
Webhook or Make failure Treat integration as optional; core flow independent
Time overrun Hard feature freeze at hour 35; nice-to-haves only after hour 24

18. Differentiator

Most document AI: Document → Question → Answer.

RulePilot: Document → Rules → Structured Logic → Workflow → Execution → Evidence → Decision → Action.

It is agentic because each component's output determines the next step, combining generative AI, RAG, multi-agent orchestration and business process automation.

19. Success Criteria

  1. A user uploads a policy PDF.
  2. Meaningful rules are extracted as structured JSON.
  3. A workflow is generated and displayed visually.
  4. A business request is submitted and checked against the rules.
  5. The decision is correct, with page and section citations.
  6. The required next action is generated.
  7. The system is deployed and accessible on Vercel.
